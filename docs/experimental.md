# Experimental prefix V8

The original implementation is preserved in `research/archive/prefix_extension_v8.py` with its exact SHA256. The importable worker changes cache/deadline configuration, capability guards, architecture-specific compilation, VRAM admission, startup qualification and formatting. The coarse/refine arithmetic and conditional prefix logic are retained. It has **not been GPU-revalidated after these changes**. Historical results describe the original script.

This is a batch-one, greedy, eight-row verification experiment for the pinned Qwen3.8-27B INT4 target with seven DFlash2 draft tokens. It uses a Marlin W8A16 coarse head, conservative score intervals, candidate refinement and dense fallback selected through CUDA conditional graphs. The original BF16 head is retained. The interval assumptions are not a formal vendor-kernel correctness proof.

The measured whole-model latency reduction was 0.922%, below the frozen >1% admission threshold. The 18.95% component improvement used an earlier numerical guard and is not interchangeable with whole-model performance. No production speedup or universal fidelity claim is justified.

The worker requires NVIDIA compute capability >=8.0 with native BF16, Linux, vLLM 0.31.0, PyTorch 2.13.0, CUDA 13.0, NVCC and `cuda.bindings` from the matching CUDA toolkit. There is no A100-name or 80GB-capacity whitelist. NVCC compiles the local CUDA conditional setter for the detected architecture, including the architecture in its cache filename. Hardware must also be supported by the installed Marlin/PyTorch kernels and toolkit. Install `.[prefix]` for the CUDA Python bindings; the package never installs a CUDA toolkit. Do not enable it on a serving process shared with other workloads.

Ineligible capability, dtype, software stack or missing NVCC/bindings keep the stock target head active and record why. The worker estimates extra packed-head/workspace memory before allocating it; this is not a guarantee against OOM. An insufficient-memory admission result also leaves the stock head active. Installation then compares 64 synthetic rows and accepted prefixes with the dense head on the actual device before enabling the hook. A finite mismatch leaves it inactive; an execution error aborts the run because CUDA context recovery cannot be assumed. Synthetic coverage is not an independent quality benchmark or proof of general numerical fidelity, and may certify few rows. The original full-model evidence remains A100-only.

The CLI supplies a new per-run build directory and a UTC deadline. Direct worker imports require `DRAFTSCOPE_CACHE_DIR` and `DRAFTSCOPE_DEADLINE_UTC`; an expired/missing deadline is rejected. Python optimization mode (`-O`) is rejected because the preserved kernel integration uses assertion-based invariants. Installation is once per worker process. Cleanup is process termination; hooks are not an in-process general-purpose patch/unpatch API.

Supported requests are greedy with no penalties, logprobs, bias, allowed-token restrictions, bad words, structured output, extra arguments or reasoning parser. Other sampler conditions use dense fallback. More than 128 stop-token IDs are rejected. On older GPUs the general Transformers path uses FP16 when the chosen model and CUDA wheel support it. An unsupported vLLM platform still requires selecting the Transformers backend explicitly; changing a backend or model is not hidden inside a speed comparison.

Before enabling it outside research: run fresh baseline/candidate comparisons with identical input IDs, paired alternating timing order, exact sequence checks, OOM/timeout checks, and an independent task-quality evaluation. These validations remain outstanding for the packaged build.
